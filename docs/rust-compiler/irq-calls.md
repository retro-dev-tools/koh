# Bounded IRQ helper calls

Interrupt roots can call ordinary scalar helpers transitively. The supported
signatures use integer32/64 and target-native16 values, including byte/word CIL
normalization and void returns. Helpers may use the existing bounded integer,
local/static and safe byte-IO subset. Reference/value aggregates, arbitrary
indirect memory, allocation, floating IR values, initialization requiring special
runtime state and nested enabling remain explicit unsupported cases. This is an
intermediate runtime capability, not a retirement of those full-migration tasks.
The executable call graph must be acyclic after lowering/optimization; CFG loops
remain allowed. The compiler establishes a stack bound, not a time/termination bound.

## One code body and calling convention

Every function reachable from an IRQ root is placed in ROM0 by canonical ELF
section kind. Shared main/IRQ helpers use one body and the ordinary four-byte
call-cookie ABI; source identity and PDB provenance are retained. The linker
still places sections and diagnoses ROM0 capacity overflow.

Far-call/return stubs inspect the CPU target address. Targets below4000 need no
MBC bank writes. This leaves the interrupted mapping intact throughout an IRQ
call chain, including an IRQ between the main program's low/high bank writes.
The decision uses the address, not a zero bank value. Tests include physical
MBC5 bankzero selected while main code resides in ROM0; canonical ROMX bankzero
sections are not supported by the current object/linker contract.

The wrapper saves AF/BC/DE/HL, allocates the ordinary cookie and calls through
the same far-call stub. Its return passes through the ordinary return stub,
then the wrapper restores the saved pairs and executes RETI. There is no second
compiler model, cloned helper implementation or shared static local frame.

## Stack bound and shared reentrancy

For each function f, calculate:

```text
need(f) = frame(f) + max(4, max over calls f→g:
    argument bytes + return bytes + cookie4 + CALL2 + need(g))
IRQ reserve = hardware PC2 + saved registers8 + cookie4 + CALL2
              + max over IRQ roots r: need(r)
```

The four-byte scratch floor covers existing internal arithmetic helper depth.
An iterative topological pass accounts for every call edge, rejects cycles and
reports oversized combined storage with member identity. It does not recurse
on the host stack. Five rstest cases cover native16/I32/I64 fits and graphs whose
outgoing argument blocks alone exceed the3840-byte physical stack.

A shared helper needs different guard limits when called by main and by an IRQ.
The generated WRAM0 byte `__koh_irq_active` is initialized tozero at startup,
set before IRQ calls and cleared before restoring registers/RETI. Main/shared
code preserves the global reserve while inactive; shared code uses the C100
floor while active. IRQ-only functions use that floor directly. All local values
remain SP-relative, permitting a separate IRQ activation of a shared helper.
Nested enabling is forbidden throughout the validated IRQ graph. Back-to-back
pending interrupts see a cleared flag and a fully restored hardware stack.
The flag consumes one WRAM0 byte, included in capacity checks. The absolute ELF
symbol `__koh_irq_stack_reserve` exposes the generated byte budget for debugging
and independent execution checks.

## Native evidence

Actual Debug/Release Roslyn DLLs and matching Portable PDBs execute in DMG/CGB
through ELF round-trip and the Rust linker. Native helper calls cover16/32/64-bit
arguments/returns, FE→FF→00 byte wrapping, a high-bit64-bit checksum with modular
overflow, full native16 results and a referenced Koh.GameBoy integer-bit helper.
The referenced helper and shared functions reside in ROM0; an unrelated software
runtime body remains dead. The bit-helper test does not claim floating IRQ support.

Real VBlank counts2/3/5 preserve all CPU registers, flags, SP, PC and both MBC5
bank registers at RETI. Ordinary caller code is exercised above bank255 and with
physical bankzero. Software requests exercise all five vectors and IE masking.
The deep-recursion mainline calls a shared native helper near the stack bound;
the adapter checks that every interruptible main boundary retains the complete
reserve, requests an IRQ at a failing guard, checks exact restoration and then
observes stack fault1 with guards intact. Test output has its own fixed WRAM0
ELF reservation, so output cannot alias compiler statics.

Matching app/reference PDBs retain helper function sources and machine-line
mappings inside each helper's code range. In Debug, the referenced method's
symbol points at its opening brace (line24), while emitted code maps to its
return/closing brace (lines25/26). The rejected exact-line assertion is recorded
in `/tmp/koh-irq-calls-pdb-diagnostic.log`; the corrected check verifies real
machine/source mapping in the right function rather than retaining an elided NOP.
KDBG v1 generation succeeds within its current bank range. Above255 it explicitly
rejects serialization; the existing native unwinder likewise rejects larger
caller banks. High-bank execution is not high-bank debugger acceptance. See
`rust/koh-link/src/debug.rs` and
`src/Emulator/Koh.Debugger/Session/NativeStackUnwinder.cs`.
