# 128-bit integers

The native compiler recognizes `System.Int128` and `System.UInt128` from a
resolved framework assembly identity. User types with matching names do not
acquire numeric semantics. Supply the Roslyn reference assemblies, including
`System.Runtime.dll`; the SDK already passes its reference paths to the compiler.
Reference assemblies are read as metadata and are never executed.

Both types use one 128-bit integer IR type, with signedness on storage,
conversions, comparisons, division and right shifts. Integer operator calls lower
directly into verified IR; framework operator stub bodies are not emitted.
Constants carry up to 64 literal bits, zero-extended to the result width.
Signed conversions explicitly extend the source sign bit. This distinction
prevents a negative 64-bit constant from silently becoming a positive 128-bit
number.

Unchecked addition, subtraction, multiplication and bitwise operations use
modulo-`2^128` arithmetic. Shift counts use their low seven bits. Signed division
truncates toward zero; signed remainder has the dividend's sign. Division by
zero and signed minimum divided by minus one use the arithmetic fault path.
The framework also computes signed remainder through division, so minimum
remainder minus one faults rather than returning zero. See the independent
[.NET Int128 implementation](https://github.com/dotnet/runtime/blob/main/src/libraries/System.Private.CoreLib/src/System/Int128.cs).

The backend keeps these values at 16 bytes; its 64-bit range analysis cannot
compress them. Existing little-endian stack slots, argument copies and memory
return buffers carry all 16 bytes. Arithmetic scratch uses three disjoint
16-byte operands and one sign byte. Existing WRAM stack and ROM capacity
diagnostics still apply. Narrower functions retain their previous scratch size.

`tests/driver/int128.rs` drives the real `WideIntegers` C# fixture through Roslyn,
canonical ELF, the Rust linker and the existing C# emulator. Expected results
come from independent Rust `u128`/`i128` arithmetic. Each result checks all 16
bytes, the complete remaining heap, return state, stack guards, and the alternate
CGB WRAM bank. Debug and Release are each exercised on DMG and CGB.

The fixture covers carry/borrow across bit 64, signed extension, multiplication,
signed/unsigned division and remainder, complement, negative/count-128 shifts,
high-limb comparisons, recursive calls, static fields, and the legacy arithmetic
round trip. Checked 128-bit operator calls and floating-point conversions receive
explicit unsupported diagnostics. Floating conversions must eventually implement
numeric conversion, rather than copying the old compiler's bit-extension behavior.

This is an implementation increment, not closure of the complete 128-bit audit.
Array/aggregate interactions, arithmetic fault execution, broader boundary cases,
metadata mutation checks and direct host-oracle comparisons still need acceptance
coverage before retiring the corresponding legacy test cases. No source-test
disposition count changes in this increment.
